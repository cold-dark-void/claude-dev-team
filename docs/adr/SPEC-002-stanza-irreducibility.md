### Stanza irreducibility — CDT-233 verdict

CDT-233 re-examined the per-site duplication this document already rejects under SPEC-002 § "Locating plugin-dir.sh itself", following on from CDT-232. It proposed one further escape beyond the two CDT-232 already rejected, and re-checked two standing decisions (`CLAUDE_PLUGIN_ROOT` forward-compat, the comment/waiver asymmetry) against what has changed since. Verdicts below; counts are dated measurements at `7957ee4`, re-derivable by the command shown, per this document's existing convention (see SPEC-002 § "Caller integration") — not a contract.

- **Q1 — three proposed escapes from per-site stanza duplication, all REJECTED-WITH-MECHANISM.**
  - **(a) A `--self` mode on `plugin-dir.sh`.** Purely circular: a caller needs `plugin-dir.sh`'s own resolved path to invoke it with `--self` in the first place, which is exactly the problem `--self` would need to solve. The prohibition already stated under SPEC-002 § "Locating plugin-dir.sh itself" — no shipped bootstrap file, no `--self` mode, "both of which would re-pose the same problem" — stands unamended.
  - **(b) A shipped bootstrap file.** Circular for the same reason already stated there: a bootstrap file that must itself be located re-poses the self-location problem one level down instead of solving it.
  - **(c) A stanza version/contract tag** (e.g. a hypothetical `# pdh-v2` marker), where an old copy of `plugin-dir.sh` is expected to *decline* an unrecognised tag rather than answer with its own (possibly stale) root. This form is genuinely **not circular** the way (a)/(b) are — it concedes the distinction between "cannot be located" and "can be located but might answer wrong" — but it fails on a separate, verified mechanism. `skills/plugin-dir.sh:459`'s `case "$sub" in` dispatches on `$1` only and never validates trailing argv, so **every already-shipped copy silently ignores an unrecognised contract tag and exits 0 with its own root** — the refusal the scheme depends on is precisely what an old copy cannot perform. Verified at `7957ee4`: `bash skills/plugin-dir.sh root --pdh-contract=2` exits 0 and prints its own root; `bash skills/plugin-dir.sh root extra-arg` exits 0. A stale copy therefore still answers authoritatively — the CDT-232 failure shape reached again, by a new door.
    - **Second, independent kill.** Relying on refusal only works if the caller also keeps the full inline ranker as a fallback for when refusal fires — so the scheme becomes find-any (locate a candidate copy) + delegate (invoke it, tagged) + refusal-detect (tell "old copy, silently wrong" apart from "new copy, correct") + full inline fallback (the entire stanza, still present, for when detection succeeds). That is **strictly longer** than today's single stanza, not shorter — self-defeating against a ticket whose premise is token cost.
    - **Honest counter-nuance, recorded rather than hidden.** A *modern* copy of `plugin-dir.sh` planted at a stale cache path self-corrects: it resolves its own real root regardless of where it happens to sit. Delegation would be safe exactly when every reachable copy is modern. The scheme has no way to know that without asking, and asking a possibly-old copy is the exact operation just shown to return exit 0 either way, stale or not.
- **Q2 — `CLAUDE_PLUGIN_ROOT` / FR #48230 forward-compat tier: no change, still UNSET in practice.** The Grok host never sets it; dev checkouts and worktrees resolve through tier 1 (cwd) instead; already-installed older builds predate any future host support and never will set it — and that stale-install population is exactly what tier 3 (cache find-fallback) exists to serve. What is new since this was last reviewed: tier 0 gained executable test coverage in v1.18.6 (CDT-237 — `skills/plugin-dir-test.sh` PASS 176 → 184, adding branch-0 positive and guard-negative assertions). "Keep the tier for forward-compat" is therefore no longer an unfalsifiable claim about 140 B of never-executed code; it is now a tested no-op on this host. That changes the tier's falsifiability, not the verdict — it remains tier 0, unset today, forward-compat only.
- **Q3 — comment-vs-waiver trim asymmetry: the waiver is load-bearing, the comment is not.**
  - The `# lint-ok: C3` waiver on the stanza's `PDH=$( {` line is **load-bearing**, not decorative. `check_c3`'s `_strip_quoted` (`skills/skill-lint/lint.py`) blanks the quoted span `"$HOME"`, leaving the unquoted `/.claude/plugins/marketplaces/*/` behind, which `GLOB_TOKEN_RE` matches. Verified at `7957ee4` in an isolated scratch copy of the tree (product tree untouched): deleting the 204 governed stanza-adjacent waiver lines alone, with nothing else changed, yields `300 findings, 96 waived`, exit 1.
  - The canonical comment line (`# Locate the dev-team plugin root (PDH).`) is genuinely ungoverned: no check reads it, and its presence or absence changes no gate's outcome. **Retention rule (would govern any future comment trim): the comment costs its token price only where the file it lives in is loaded into a model context, so it is dropped there and kept everywhere that cost is never paid.** A standalone `.sh` whose only in-repo documentation of a 746 B line is that comment, and reader-facing prose under `docs/runbooks/`, keep it; a `.md` skill/command/agent source that gets read into a prompt drops it. This is a rule evaluated by file kind, not a fixed list of exceptions.
  - **Trim considered and declined — CDT-233.** The rule above was fully prototyped: every stanza-adjacent comment line dropped per the rule, in an isolated scratch copy of the tree at `7957ee4` (product tree untouched), with all gates re-run green and no red window at any commit boundary. It was declined on **value**, not feasibility. Measured saving: **23,375 B**, which is **15.0%** of the stanza payload but only **1.2%** of the **~1,978,055 B** `.md` prompt corpus (dated measurement at `7957ee4`; re-derive the denominator with `find commands skills agents -name '*.md' | xargs wc -c | tail -1`). Best single file `skills/release-train/SKILL.md` at about −6%; `skills/init-orchestration/SKILL.md` and `skills/bug-hunt/SKILL.md` at −0%. The waiver half of the same trim additionally required a `skills/skill-lint/lint.py` rule change — a byte-identity-conditioned auto-waiver — argued against SPEC-021's standing "do not weaken the check" MUST: a real cost, for that 1.2%. The genuine lever is elsewhere and is not safely pullable: the CDT-166 `awk` version-segment ranker is roughly **52%** of the 746 B stanza line (~63 KB tree-wide), and Q1 above is precisely the finding that it cannot be removed safely. This is a value judgement at a measured ratio, not a closed question — it re-opens if the ratio changes materially, e.g. emission count grows substantially, or a mechanism appears that reduces the ranker itself rather than the surrounding comments.
  - **Correcting the record.** The SPEC-002 § "Caller integration" section previously claimed every site emits "one comment line + one `PDH=` assignment." That claim is already false and no gate checks it. Verified at `7957ee4`: `grep -rn '^ *# Locate the dev-team plugin root (PDH)\.' commands skills agents docs | wc -l` → `22`, against `209` real stanza emissions (`grep -rn 'PDH=\$( {' commands skills agents docs | wc -l` → `215` raw, minus 3 prose mentions in `skills/plugin-dir-test.sh`, 1 decoy in `skills/skill-lint/test.sh`, and 2 deliberately drifted copies in `skills/skill-lint/fixtures/` → `209`; C3-lint-visible count over the same tree, `bash skills/skill-lint/check-skill-bash.sh --json | tr '{' '\n{' | grep -c '"check": "C3"'` → `204`). 22 of 209 is not "every site"; the sentence is corrected below to state that the comment is not required at every site and to point at the retention rule above, rather than restate the false universal.
- **Q4 — this section is the anti-re-litigation record itself.** Filed against CDT-232, which rejected the `--self`-mode and shipped-bootstrap-file escapes on circularity — restated verbatim as Q1(a)/(b) above — and CDT-233, which raised and rejected the stanza-version-tag escape (Q1(c)) and re-examined Q2 and Q3. A future ticket proposing a fourth escape from per-site stanza duplication, re-opening `CLAUDE_PLUGIN_ROOT` as a general solution, or arguing the comment/waiver asymmetry is inconsistent, MUST read Q1–Q3 above — and CDT-232 itself for the two mechanisms Q1(a)/(b) restate — before re-deriving the same reasoning. The counts under Q2 and Q3 are dated measurements at `7957ee4`; the mechanisms and the rules they support are not.
