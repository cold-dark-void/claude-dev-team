### Overlap / routing analysis
- **debug vs bug-hunt vs fix-ticket:** the split is correct (known bug → `/debug`; unknown bugs → `/bug-hunt`; ticketed premise → `/debug ticket` → `skills/fix-ticket`). Problems:
  - `fix-ticket`, `standup`, `scaffold-project`, `security-scan`, `blunt` and `focus` all describe themselves as internal / "not a user entry", yet all still appear in the `/` menu and in auto-discovery. Add `user-invocable: false`, plus `disable-model-invocation: true` where auto-trigger is harmful.
  - `commands/{debug,bug-hunt,craft-loop}.md` and their skills share a `name:`, which duplicates the menu entry.
  - SPEC-014:44 still requires fix-ticket deprecation stubs, and L64/69/70 name `/update-spec`. The skill has moved on (permanent backend; `/spec update`), so the spec is stale.
  - SPEC-014:80 says test-first applies to "all modes", but arch mode forbids tests.
- **refactor vs code-simplify:** keep them separate (design-first restructure vs a narrow polish pass inside `/orchestrate`). Two changes:
  - Route a manual code-simplify run with no orchestrate context to `/refactor`.
  - Rename code-simplify (e.g. `post-approve-polish`) so it doesn't collide with the built-in `/simplify`.
- **review-and-commit vs `/council --diff`:** `commands/council.md:30` calls them "equivalent", but review-and-commit adds SAST, `--impact`, the legacy render and the commit gate, and always runs the full tier. Consolidate by making review-and-commit literally `council --diff --tier full` plus a `commit-gate` post-step, and move the Step 6 render into `skills/council/templates/`. That would have prevented the category-mapping drift.
- **focus / blunt / `/mode`:** fine as orthogonal session modes; just fix the invocability.
