# Review 08: Diagnostics (doctor, bug-hunt, debug, retro, retro-gate)

Reviewer slice: `slices/08-diagnostics.txt` (53 files). Read-only review; all findings verified by reading code and/or running the command noted, unless marked "(unverified)".

## Slice summary

- **What it does:** `/doctor` is a deterministic, offline install and config health check (`doctor.sh`, 24 checks, PASS/WARN/FAIL/SKIP, `--json`, `--fix`, `--gate`). `/debug` is a phase-gated root-cause, then test, then fix pipeline, with SPEC-029 reopen/redesign gates (`theme-status.sh`) and a `ticket` mode that delegates to `fix-ticket` and the `debugger` agent. `/bug-hunt` runs a 4-stage unknown-defect pipeline: blind discover, refute, report, plan and proceed-gated backlog materialize, then emit-only phase handoff. `/retro` is a two-phase friction retrospective: `gate.sh` heuristic, a haiku deep-read subagent, dedup and apply, directive trials (CDV-200), and a scheduled `--all --auto` mode with a lock and a report.
- **Overall grade: C+.** The scripts that can be tested in isolation (`doctor.sh`, `gate.sh`, `trial-*.sh`, `scheduled-lock.sh`, `write-scheduled-report.sh`) are solid and well tested (doctor 102/0, retro-gate 27/0, trial-meta 21/0, trial-review 19/0, write-report 22/0, lock 8/0, bug-hunt static 206/0). The problems sit where the LLM-driven orchestration (`commands/retro.md`, `skills/bug-hunt/SKILL.md`) meets shell semantics.
- **Biggest risk 1 (P1):** the `/retro --all --auto` scheduled path relies on shell state that does not carry across fences. The `EXIT` trap releases the lock as soon as the Step 1b fence exits, and `write_scheduled_report_if_needed` is defined in one fence but called from four others. The concurrency guard and the "always write a report" guarantee therefore do not hold as written. 60 `lint-ok` waivers in `retro.md` hide this.
- **Biggest risk 2 (P1):** on consumer installs the SPEC-029 reopen gate in `/debug` can silently disable itself. `theme-status.sh` is found through `$MROOT/skills/...` or `$CLAUDE_PLUGIN_ROOT`, not through the PDH/`plugin-dir.sh` stanza. When neither resolves, the inline fallback always prints `REOPEN_COUNT=0`.
- **Biggest risk 3:** two test scripts fail on a clean checkout: `friction-capture-test.sh` needs the gitignored generated hook, and `scheduled-retro-test.sh` has a stale grep. CI runs only `skills/retro-gate/test.sh`. `doctor/test.sh`, `bug-hunt/test.sh` and the six other retro-gate tests are not in CI, and `theme-status.sh` and `hint.sh` have no tests at all.
- **Token cost:** `skills/bug-hunt/SKILL.md` is 135 KB (~34K tokens, 3391 lines) and is read in full on every `/bug-hunt`. `commands/retro.md` is 87 KB, `skills/debug/SKILL.md` 52 KB. The PDH stanza appears 12 times in `retro.md` and 6 times in the bug-hunt skill. The Model-map fence and the traceability/fill-in-map tables are runtime dead weight.
- **Doc drift:** `retro-gate/SKILL.md` S3 semantics contradict `gate.sh` and its own test (CDT-125). `docs/commands/debug.md` has a stale `/fix-ticket` removal version, and its `patch` description and example checklist are out of date. The bug-hunt `report.md` template still says stages 3–4 are future work.
- **Portability:** several `value=${2:-}; shift 2` parsers loop forever on a trailing flag. `grep -c … || echo 0` produces `0\n0`, which breaks the `[ -eq ]` checks in `retro.md`. Project-dir encoding differs between files (`s|/|-|g` vs the non-alnum rule in `hint.sh`). A few GNU-only constructs remain (`find -printf`, `touch -d '2 minutes ago'`).

## Findings

1. **[P1] `/retro --all --auto`: the scheduled lock releases immediately, and the report helper is undefined in later fences.** `commands/retro.md:150` sets `trap '… release …' EXIT` inside the Step 1b fence. Fences are separate shells (the file itself says so at l.234 and l.613), so the trap fires as soon as that fence ends. Simulated: acquire+trap in one `bash -c`, then a second `acquire` returned **0** (should be 2). Likewise `write_scheduled_report_if_needed()` is defined at l.157 but called from fences at l.602, 745, 1521 and 1962, where it is `command not found`. Nothing verifies that a report is written, and l.1899 explicitly relies on "The EXIT trap from Step 1b". *Fix:* move the lock and report into a single subprocess CLI, e.g. `skills/retro-gate/scheduled-run.sh {begin|end}`. `begin` acquires the lock and writes a session token file under `.claude/retro/`. Each exit site calls `bash "$SCHED_WRITER" …` directly (inline flags, no shell function), then calls `scheduled-lock.sh release` explicitly. Drop the trap. Add an integration test that executes the extracted fences in separate shells.
2. **[P1] `/debug` SPEC-029 reopen gate can silently no-op on installed plugins.** `skills/debug/SKILL.md:316-321` looks for `theme-status.sh` only at `$MROOT/skills/debug/…` (the user's repo) and `${CLAUDE_PLUGIN_ROOT:-}/…`. AGENTS.md treats `CLAUDE_PLUGIN_ROOT` as optional and requires `plugin-dir.sh` resolution. When neither is found, the fallback (l.326-335) always prints `REOPEN_COUNT=0 / FORCED_REDESIGN=no`, which disables the "force redesign after ≥2 prior days" MUST without any warning. The same skill already uses PDH for fix-ticket (l.889). *Fix:* use the PDH stanza plus `bash "$PDH/skills/plugin-dir.sh" file skills/debug/theme-status.sh`. On failure print `WARN: theme-status.sh unresolved — SPEC-029 reopen count unavailable` instead of silently asserting 0.
3. **[P2] Two tests fail on a clean checkout, and most of the slice's tests are not in CI.** `bash skills/retro-gate/friction-capture-test.sh` gives `FAIL: missing …/.claude/hooks/friction-capture.sh` (the path is gitignored, `.gitignore` l.5). `bash skills/retro-gate/scheduled-retro-test.sh` gives `PASS=10 FAIL=1` ("Filter 2 missing"): the grep `command-name.*/[a-z:-]*retro` cannot match the literal regex text in `retro.md:575`. `.github/workflows/smoke.yml` runs only `skills/retro-gate/test.sh`. *Fix:* have friction-capture-test extract the Step 4g template from `skills/init-orchestration/SKILL.md` into `$TMP`, and change the Filter-2 check to `grep -qF '<command-name>/[a-z:-]*retro</command-name>'`. Add a CI job that loops over `skills/retro-gate/*-test.sh`, `skills/doctor/test.sh` and `skills/bug-hunt/test.sh`.
4. **[P2] `scheduled-lock.sh` acquire is racy (TOCTOU).** `scheduled-lock.sh:81-110` checks `[ -f "$LOCK" ]`, then `printf > tmp; mv -f tmp LOCK`. Two cron fires in the same second both see no lock and both return 0. `release` (l.114) removes any lock regardless of owner. *Fix:* acquire with `mkdir "$LOCK.d"` (atomic) or `set -C; : > "$LOCK"`, steal stale locks via rename, and record/verify the pid on release. Add a parallel-acquire test.
5. **[P2] The retro-gate SKILL documents S3 semantics that `gate.sh` no longer implements.** `skills/retro-gate/SKILL.md:78`: "Pre-existing paths and dirty session-created paths still score." In `gate.sh:387-398` (CDT-125) any window without an intervening error or S1 is skipped regardless of path origin, and `test.sh` AC3 asserts that pre-existing clean Edit×3 gives no S3. `bash gate.sh fixtures/ac3-preexisting-thrash.jsonl` gives `score 0.0`. `s3_first_tool` (gate.sh:137, 222) is dead. *Fix:* rewrite the S3 row to "scores only windows with an intervening tool error or S1 rejection (CDT-125); clean multi-edit, whether Write-first or pre-existing, never scores". Delete `s3_first_tool` and rename the AC3 fixture.
6. **[P2] `grep -c … || echo 0` yields a two-line `0\n0` in `commands/retro.md`.** At l.465 (`_gc`), 473 (`SESSION_COUNT`), 591 (`SCANNED`) and 1957-1959 (`DUP_N`/`MF_N`/`OBS_N`), and also l.1676/1774 when the file exists but is empty. Verified: `[ "0\n0" -eq 0 ]` gives `integer expression expected`, and the branch is not taken. The result is that `/retro --all --host grok` with zero Grok sessions skips its intended error. The scheduled summary also embeds a newline ("Duplicates: 0\n0"). *Fix:* use `n=$(grep -c . f 2>/dev/null); n=${n:-0}` (grep -c already prints 0) or `awk 'END{print NR}'`.
7. **[P2] The `/retro --all` recurrence filter is computed on a truncated, per-proposal set.** Step 4e caps to the top 5 (`retro.md:1107`) *before* Step 4f/5a build `SINGLETON_PATTERNS` (l.1121). Counts are per proposal row, not per distinct `source_jsonl`. As a result, a pattern that recurs across sessions but ranks 6th is lost, and two proposals from one session with the same `pattern_summary` pass the "2+ sessions" MUST. *Fix:* in `--all`, run the singleton filter first with `cut -f5,7 | sort -u | cut -f1 | uniq -c`, and cap to the top 5 afterwards.
8. **[P2] The scheduled report's "Applied" list overstates.** `retro.md:1918-1930` writes every NEW/TIGHTEN row of `ACTIONABLE_PROPOSALS` to `APPLIED_FILE`. The comment says "not parked in MANUAL_FOLLOWUP", but no such exclusion exists. *Fix:* append to an `APPLIED_ROWS` accumulator at the actual success points (the exit-0 branches in Step 6c) and write that.
9. **[P2] `/debug` Step 0c path sanitizer rejects every relative path, which then makes `git log` fatal.** `skills/debug/SKILL.md:250`/`274`: `[[ "$SAFE_PATH" != "$WTROOT"* ]] && SAFE_PATH=""` empties any repo-relative path such as `src/auth`. Then l.251 runs `git log --oneline -20 -- ""`, which fails with `fatal: empty string is not a valid pathspec` (rc 128, verified), and l.277 falls back to `find .`. *Fix:* resolve relative paths against `$WTROOT` (`case $SAFE_PATH in /*) ;; *) SAFE_PATH="$WTROOT/$SAFE_PATH";; esac`) and guard with `[ -n "$SAFE_PATH" ] && git log …`.
10. **[P2] `doctor --fix` ignores `--only`.** `doctor.sh:1734` runs `do_fix` (all 3 repairs) before the filtered battery. `test.sh` T7b (`--fix --only worktree.distill_lock`) implicitly also sweeps wt-locks and tmp. Users of `--fix --only memory` would not expect `.wt-lock` removal. *Fix:* gate each repair with `should_run` for its owning id (`worktree.distill_lock`, `worktree.locks`, a new `handoff.tmp`), or document that the two flags don't combine and reject `--fix --only` with exit 64.
